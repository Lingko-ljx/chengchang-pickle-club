# 微信公众号运营接入清单

本文档用于把现有公开 H5 预约站接入任意微信公众号，不依赖公众号名称、AppID 或具体域名。首版只让公众号菜单在微信内置浏览器中打开 H5；这不是 iframe，也不需要重做小程序。

## 1. 首版架构

```text
公众号自定义菜单 / 自动回复 / 宣传物料二维码
                    |
                    v
           公开 HTTPS H5 预约站
                    |
                    v
        CloudBase 公开预约 API 与数据库

工作人员单独访问 /admin/ -> CloudBase Auth -> 管理 API
```

首版不接 OAuth、不接 JS-SDK、不开发小程序。顾客继续在公开 H5 中填写姓名和手机号并完成预约；工作人员后台保持独立登录。这样可最快开始运营，也不会把后台权限与公众号流量混在一起。

## 2. 三项菜单模板

模板文件为 [`wechat-menu-template.json`](wechat-menu-template.json)，其中只包含微信 `view` 类型菜单的通用结构。发布前必须替换以下三个占位符，替换后的值必须是完整的 HTTPS URL：

| 占位符 | 菜单 | 推荐目标 |
| --- | --- | --- |
| `{{BOOKING_MENU_URL}}` | 预约场地 | 直接进入正式预约页；使用 `src=wx_menu` |
| `{{DAILY_MENU_URL}}` | 球馆动态 | 首页每日图片/视频区域或最新公众号图文；站内链接使用 `src=wx_menu` |
| `{{CONTACT_MENU_URL}}` | 联系我们 | 地址、电话、营业时间和交通说明页；站内链接使用 `src=wx_menu` |

如果目前只有一个稳定首页，三个菜单可以在首日暂时指向同一个首页，但应尽快提供明确的页面区块或稳定深链接，避免用户每次自行寻找内容。

可以在微信公众平台后台手工创建这三个菜单，也可以在确认账号接口权限后把替换完成的 JSON 作为菜单 API 请求体。模板不是密钥文件，不得向其中加入 AppID、AppSecret、access token 或工作人员账号。

发布菜单后，微信客户端可能不会立刻刷新。重新进入公众号会话页并等待平台同步后再验收，不要因为短暂缓存重复发布多份菜单。

## 3. 关注自动回复文案

以下文案不依赖公众号名称。把 `{{BOOKING_MENU_URL}}` 替换为正式 HTTPS 地址；若公众平台对消息内链接的展示有限制，以底部菜单为主。

```text
欢迎关注！

预约场地：点击公众号底部「预约场地」
每日照片和视频：点击「球馆动态」
地址、电话和营业信息：点击「联系我们」

如菜单暂未显示，可打开：{{BOOKING_MENU_URL}}
```

不要在自动回复中发送后台地址、工作人员用户名、测试环境地址或任何密钥。

## 4. 两类二维码怎么用

二维码的目标不同，不应只用“公众号二维码”笼统描述。

### 公众号二维码

- 扫码后进入公众号关注页，适合门店主海报、社交平台主页和长期沉淀粉丝。
- 关注后通过自动回复和底部「预约场地」进入 H5，比网页二维码多一步。
- 使用微信公众平台下载的官方二维码原图，不要从聊天截图中裁切或二次压缩。
- 若账号具备带参数二维码权限，可在后续用不含个人信息的场景值区分门店、活动或合作渠道；首版不必接该接口。

### 预约网页二维码

- 扫码后直接打开公开 H5，预约转化路径最短，适合前台、球场边和临时活动。
- 预约网页二维码统一使用严格白名单参数 `src=wx_qr`，不得自造其他值，也不得包含姓名、手机号、OpenID 或预约号。
- 大批量印刷前，应让二维码指向可长期控制的自有 HTTPS 域名；否则将来换托管地址需要重印。

主海报推荐使用公众号二维码并明确写“关注后点击预约场地”。前台可补充一个清楚标注的“立即预约”网页二维码。若一张物料同时放两个码，必须用不同标题和操作说明，避免用户扫错。

公众号文章内的手机用户已经在微信中，优先提示点击底部菜单或“阅读原文”，不要强迫用户再识别文章图片中的二维码。

所有二维码在批量发布前都要用微信扫一扫和图片长按识别实测；保持高对比、完整留白和足够印刷尺寸，不用未经验证的艺术化二维码。

## 5. 切换到自有域名

当前 CloudBase 默认 HTTPS 域名可以先用于菜单和电子传播。为了让长期物料不受托管平台地址变化影响，正式印刷前推荐准备一个由运营方控制的稳定域名，例如 `book.example.cn`。不要把本示例域名直接用于生产。

切换顺序：

1. 完成域名实名、适用的备案要求、DNS、HTTPS 证书和 CloudBase 自定义域名绑定。
2. 按微信公众平台当时显示的要求放置域名验证文件，并只配置当前功能需要的业务域名。
3. 更新站点发布配置和公开结果链接；保持旧 CloudBase 地址可回退，先不要撤下旧入口。
4. 把新站点的**精确 Origin**加入公开 API 的 `PUBLIC_ALLOWED_ORIGINS`，并验证未列入的 Origin 仍然被拒绝。不得用 `*` 代替。
5. 如果工作人员后台也改为从新域名访问，还要同步验证管理 API CORS、CloudBase Web 安全来源和 Storage 直传 CORS；只更换 DNS 不代表后台媒体上传会自动可用。
6. 在微信 iOS、Android 和普通浏览器完成全流程验收后，再更新公众号菜单、自动回复和网页二维码。
7. 保留旧链接一段观察期；确认无旧物料流量后再决定是否做受控跳转或下线。

大量印刷前先完成域名切换。若暂时没有自有域名，只发布电子二维码并保留可替换的物料源文件。

## 6. 何时才需要 OAuth

满足以下条件之一，再设计公众号网页 OAuth：

- 需要基于 OpenID 提供“我的预约”；
- 需要把公众号用户与现有预约身份绑定；
- 需要在账号权限和平台规则允许的前提下发送预约相关公众号通知。

实施前必须确认公众号类型、认证状态和“接口权限”页面确实开放网页授权，并配置网页授权回调域名。OAuth 只能辅助识别微信用户，不能替代手机号的显式填写或验证。

授权码换 token、AppSecret 使用和用户绑定必须发生在服务端。回调必须校验 `state`/随机会话、限制允许跳转地址并防止重放；不得把 AppSecret、access token、refresh token 或 OpenID 写入前端包、URL 日志或二维码。获取和使用个人信息前应提供清晰告知并遵守数据最小化原则。

## 7. 何时才需要 JS-SDK

只有在需要自定义微信分享卡片、微信扫码、定位等微信专属能力时才接 JS-SDK。普通菜单打开、浏览每日动态和提交预约不依赖 JS-SDK。

实施前必须确认账号权限并配置 JS 接口安全域名。`jsapi_ticket`、AppSecret 和签名逻辑只能在服务端；前端只接收短期、与当前页面 URL 绑定的签名参数。必须校验动态 URL、缓存周期和失败降级，确保 JS-SDK 不可用时基础预约仍然能完成。

小程序放在更后阶段：只有在明确需要微信支付、会员卡、套餐、优惠券、订阅消息、多门店或更强留存体验时再立项。小程序需要独立前端适配、账号/认证、隐私声明、服务域名配置和平台审核，不是首版 H5 接入的前置条件。

## 8. iOS 与 Android 微信验收清单

每次修改菜单、域名、授权或分享能力后，至少各用一台近期 iPhone 和 Android 真机，在微信内完成以下检查：

- [ ] 公众号底部显示「预约场地」「球馆动态」「联系我们」三项，名称和顺序正确。
- [ ] 三个菜单均在微信内置浏览器打开正确的 HTTPS 页面，没有证书告警、危险提示或空白页。
- [ ] 预约页显示北京时间，营业范围为 09:00–22:00，整点和半点开始时间可选。
- [ ] 开始和结束时间明确，1–4 小时规则正确，例如 09:30–11:30 可选，越界时间不可选。
- [ ] 用合成测试姓名和测试手机号完成一笔预约；页面成功结果、后台姓名、场地和时间完全一致。
- [ ] 返回、刷新和弱网重试不会重复创建预约；完成验收后取消并清理测试预约。
- [ ] 首页图片可查看，MP4 视频能由用户点击播放；不把移动端自动播放当作通过条件。
- [ ] 「联系我们」中的地址、电话、营业时间可读，电话行为符合预期。
- [ ] 微信返回手势、系统字体放大、键盘弹出和小屏滚动不会遮挡提交按钮或关键提示。
- [ ] Wi-Fi 与移动网络各完成一次公开页面和预约 API 检查。
- [ ] 公众号二维码可由相机扫描，网页二维码既可扫描也可从图片长按识别。
- [ ] 分享给好友后打开的是公开页面，不是 `/admin/`、测试环境或失效签名 URL。
- [ ] 未接 JS-SDK 时默认分享仍可打开；已接 JS-SDK 时分享标题、封面、落地页和失败降级均正确。

记录验收日期、微信版本、设备系统、菜单版本、目标域名和测试预约清理结果。任一平台失败时停止批量发码和印刷，修复后两端重测。

## 9. 安全红线

- 永远不在公众号菜单、文章、自动回复、二维码或分享卡片中公开 `/admin/`。
- 永远不把 AppSecret、access token、`jsapi_ticket`、CloudBase/CAM 密钥、工作人员密码或盐值写入前端、模板、本仓库、截图或日志。
- 所有运营入口只使用 HTTPS；API 和 Storage CORS 使用精确允许列表，不使用通配符放宽访问。
- 二维码和 `src` 等查询参数只放无个人含义的活动标识，不放手机号、姓名、OpenID、预约号或管理凭据。
- OAuth 回调校验状态和允许跳转地址；公众号消息服务器启用后必须校验微信签名，并按平台要求安全保管消息密钥。
- 不能仅凭 URL 参数、客户端 OpenID 或“来自微信浏览器”判断用户权限；后台仍由 CloudBase Auth 和服务端允许列表保护。
- 不因公众号接入而开放数据库客户端访问、匿名 Storage 写入或公开对象列表；预约和媒体仍通过现有服务端授权边界。
- 未确认账号接口权限，不承诺 OAuth、带参二维码、JS-SDK、通知或支付能力；以公众号后台当前“接口权限”和平台规则为准。
- 未完成真机验收和稳定域名确认，不批量印刷二维码或对外宣称正式接入完成。
