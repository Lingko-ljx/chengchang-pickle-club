# 澄场网站兼容版与真实预约设计

## 目标

在保留“澄场 PICKLE CLUB”现有中文内容、高端编辑式视觉和 GitHub Pages 公共网址的前提下：

- 让核心介绍内容在不支持现代 JavaScript 的旧 Android WebView 中仍可阅读。
- 把预约演示改为真实预约意向收集。
- 每次成功提交后保存后台记录，并向运营者发送邮件提醒。
- 预约由运营者人工联系确认，不实现实时余位、自动确认、取消、付款或会员系统。
- 不要求当前购买独立域名；以后可绑定域名而不改预约数据结构。

## 已确认的业务边界

- 主站继续使用 `https://lingko-ljx.github.io/chengchang-pickle-club/`。
- 预约记录默认为“待人工确认”。
- 网站访客填写期望日期、时段、人数、称呼和联系电话。
- 当前版本只收集预约意向，不声称对应场次已经锁定。
- 邮件接收地址不写入公开仓库，由后台服务账号管理。
- 独立域名是后续增强项，不阻塞本次改造。

## 方案选择

采用“静态兼容主站 + 原生预约表单 + 托管表单后台”。

首版后台使用 Formspree：

- 标准 HTML 表单可以在没有 JavaScript 时直接提交。
- 提交内容保存在 Formspree 后台，并可向指定邮箱发送通知。
- 免费方案目前提供每月 50 次提交及 30 天提交历史，适合首版验证；超过该规模或需要长期留存时，再迁移到自有数据库。
- 表单 endpoint 是公开提交地址，不把邮箱密码、API 管理密钥或其他凭据写入前端。

不采用现有 `chatgpt.site` 作为预约 API，因为用户已经遇到该域名的访问拦截；也不在 GitHub Pages 中伪造后端能力，因为 GitHub Pages 只能托管静态文件。

## 前端架构

### 静态输出

- 保留现有 Next.js 源码作为内容维护入口和 Sites 预览入口。
- GitHub Pages 构建继续输出完整静态 HTML 和 CSS。
- GitHub Pages 发布产物移除 Next/React 客户端运行脚本；正文、导航和预约表单均不依赖 hydration。
- 只保留一个小型、可选的兼容增强脚本。脚本失败或被禁用时，浏览器仍使用原生 HTML 表单提交。

这样可以保持一份主要内容源码，同时避免在旧 WebView 中执行 Next.js 16 运行时包含的现代语法。

### 预约表单

预约区域改为语义化原生表单：

- 日期使用 `input[type="date"]`，不支持该控件的旧浏览器会退化为文本输入。
- 时段和人数使用原生 `select`。
- 称呼和联系电话使用带 `name`、`autocomplete` 和 `required` 的输入框。
- 增加必选的个人信息使用告知与同意项。
- 增加隐藏的来源、提交状态和反垃圾字段。
- 表单 `method="POST"`，`action` 指向构建时注入的 Formspree endpoint。

增强脚本负责：

- 在支持 XMLHttpRequest 的浏览器中原地提交并显示成功或失败状态。
- 提交期间禁用按钮，减少重复预约。
- 只有后台返回成功状态后才显示“已收到预约意向”。
- 若脚本不可用，直接执行浏览器原生表单提交，仍能保存记录并发送邮件。

### 兼容 CSS

保持现代浏览器中的现有视觉，同时补充旧内核 fallback：

- 在 `clamp()` 前提供固定或视口字号。
- 为 `aspect-ratio` 提供等比例高度 fallback。
- 在 `inset`、逻辑边距和逻辑内边距前提供物理方向属性。
- 为关键 Flex/Grid 布局提供单列或相邻间距 fallback。
- 不使用隐藏整个页面后等待脚本显示的模式。

## 数据流

1. 用户打开 GitHub Pages 静态页面。
2. 用户填写预约意向并同意信息使用说明。
3. 浏览器把表单提交到 Formspree。
4. Formspree 校验请求、执行垃圾信息过滤并保存提交。
5. Formspree 向运营邮箱发送新预约提醒。
6. 页面仅在收到成功响应后显示预约已收取；文案明确说明仍需人工确认。
7. 运营者在邮箱或 Formspree 后台查看记录并电话联系用户。

首版字段：

- `preferred_date`
- `preferred_time`
- `party_size`
- `name`
- `phone`
- `privacy_consent`
- `status`，固定为 `pending`
- `source`，固定为公开站点标识

## 隐私与安全

- 页面明确说明姓名和电话只用于预约联系。
- 不在浏览器本地持久化个人信息。
- 不在公开仓库保存收件邮箱密码或后台管理密钥。
- 通过后台设置限制允许提交的站点来源。
- 使用蜜罐字段和后台垃圾信息过滤；超出频率时显示稍后再试。
- 免费后台仅保留 30 天历史；正式运营前由运营者决定是否升级或迁移以满足更长留存要求。

## 错误处理

- 必填项缺失时优先使用原生浏览器校验，并提供中文提示。
- 后台拒绝、限流或网络失败时保留表单内容，显示“提交未成功，请稍后重试或电话联系”。
- 不以按钮点击作为成功依据，不产生虚假预约确认。
- JavaScript 语法或运行时失败时，原生表单仍可提交。
- 如果目标 Android 应用直接拦截 `github.io`，页面代码无法绕过域名级拦截；此时需要独立域名或另一托管入口。

## 发布与后续修改

- GitHub Pages 工作流从同一仓库构建并发布兼容产物。
- Formspree form ID 通过 GitHub Actions 变量注入；没有有效 endpoint 时构建失败，不发布不可用的预约表单。
- 更新文字、人员、奖项、联系方式或样式后，只需重新构建发布，公开网址保持不变。
- 后续绑定独立域名时修改 Pages 设置、DNS、站点根路径和公开网址配置；预约后台与历史记录不受影响。

## 验证

自动验证：

- 构建产物包含完整中文正文和原生预约表单。
- 发布 HTML 不包含 Next/React 客户端脚本。
- 表单包含 `POST` action、所有命名字段、必填项和隐私同意项。
- CSS 包含关键旧浏览器 fallback。
- 未配置预约 endpoint 时构建明确失败。
- 现有内容、元数据和 GitHub Pages 子路径检查继续通过。

人工验证：

- 桌面 Chrome、Edge 和 Firefox。
- iPhone Safari。
- Android Chrome 与 Android System WebView。
- 微信或其他应用内置浏览器。
- JavaScript 禁用场景。
- 使用测试预约验证后台留存和邮件提醒，然后删除测试个人信息。

## 范围外

- 自动管理时段库存或防止多人选择同一时段。
- 自动确认、取消、改期、支付或退款。
- 登录、会员系统和公开管理后台。
- 当前购买或绑定独立域名。
- 承诺任何会主动屏蔽 `github.io` 的应用都能访问。
